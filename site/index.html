Effortlessly keep accurate tabs on your distributed AI workflows

StatusPan is an open-source, super fast control panel for AI agents. One local Go binary draws an airport departures board. Bots push one way, with one curl. A running job that goes quiet is stalled, then abandoned. A Cloudflare relay is optional if you want to self-host it. A hosted paid version is coming soon.

Quick start

Point your AI agent to https://statuspan.com/skill.md and it will know what to do.

How to install by a human…
  1. 01
    Install 
    curl -fsSL https://statuspan.com/install.sh | sh

    The script detects your OS and architecture and installs the release binary to /usr/local/bin when you are root or that directory is writable, otherwise to ~/.local/bin. After install, run command -v statuspan. If nothing is found, add the install directory to PATH or call the binary by its full path.

    command -v statuspan || export PATH="/usr/local/bin:$HOME/.local/bin:$PATH"
  2. 02
    Serve 
    statuspan serve

    Starts the local daemon. It refuses any address that is not loopback.

  3. 03
    Open

    http://localhost:4477

  4. 04
    Tell your agent 
    statuspan agent
statuspan agent install
# example: wrap any command
statuspan run --agent "My Agent" --job hello -- sleep 5

    statuspan agent prints the skill. statuspan agent install writes it where agents look. statuspan run wraps a command, posts running then done or failed, and keeps that command's exit code. The last two lines are only an example of wrapping your own command. sleep 5 is a harmless demo.

  5. 05
    Post your first job

    Use statuspan post. The CLI posts to the relay when STATUSPAN_RELAY_URL, STATUSPAN_RELAY_WORKSPACE, and STATUSPAN_TOKEN_FILE are set, and to the local daemon otherwise.

    statuspan post --agent "My Agent" --job build-1 --state running --progress 40

    As a backup, you can always use the URL with plain curl, as long as the URL is the one where StatusPan is actually running.

    curl -s -X POST "${STATUSPAN_URL:-http://127.0.0.1:4477/api/jobs}" -H 'Content-Type: application/json' -d '{"agent":"My Agent","job_id":"build-1","state":"running","progress":40}'

    Reload the board. My Agent / build-1 shows as running.

FAQ

QuestionAnswerStatus
Can I see agents on other machines? Yes. StatusPan works well when your agents run across different environments — your laptop, servers, GPU boxes, and cloud agents — and you want one report of who's where and what they're doing. Remote machines post through the relay, and each update is stamped with the token, IP, and country that sent it, so you know where it really came from. Relay
How does an agent post a job? Use statuspan post (or statuspan run). The CLI posts to the relay when STATUSPAN_RELAY_URL, STATUSPAN_RELAY_WORKSPACE, and STATUSPAN_TOKEN_FILE are set, and to the local daemon otherwise. As a backup, you can always use the URL with plain curl, as long as the URL is the one where StatusPan is actually running. A new job needs agent, job_id, and state: queued, running, blocked, done, or failed. Later posts may omit state. The local daemon has no auth. Push
What are stalled and abandoned? A running job with no heartbeat for ttl seconds (default 600) is stalled. Abandoned is later: max(24h, 4 × ttl) of silence for a running job, and 7 days for queued or blocked. Done and failed are never abandoned. Both are derived at read time. Agents cannot post them. A newer applied post revives the job. Derived
Should a recurring job go on the board? Healthy recurring jobs and scheduled routines stay off the board. If a recurring job becomes blocked or failed, post it so it shows under Needs attention. Once it is fixed or unblocked, post done so it clears out. Attention
What if StatusPan is offline? Posting is fire-and-forget. If the daemon is down, keep doing the real work. The board is loopback only. An agent on another machine can post to a self-hosted relay with a write token (spw_). The daemon pulls that workspace with a read token (spr_). StatusPan never calls the agent back. Local
